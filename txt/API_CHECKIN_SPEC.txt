================================================================================
        XÂY DỰNG API CHECK-IN SỰ KIỆN
   (Lookup QR · Confirm Check-in · Undo Check-in)
================================================================================

Phạm vi: Thiết kế toàn bộ API và giao diện quét mã QR phục vụ check-in
tại cổng sự kiện, bao gồm tra cứu mã, xác nhận check-in và hoàn tác check-in.

================================================================================
PHẦN 1 — TỔNG QUAN KIẾN TRÚC API CHECK-IN
================================================================================

BASE URL  : /admin/checkin
AUTH      : Yêu cầu đăng nhập Admin (middleware: auth, can:manage-checkin)
FORMAT    : JSON (Content-Type: application/json)
METHOD    : POST cho tất cả endpoint thao tác dữ liệu

Sơ đồ luồng:

  [Nhân viên quét QR tại cổng]
          │
          ▼
  [Giao diện Quét — /admin/checkin]   ← Camera QR hoặc nhập tay
          │
          │── Bước 1 ──► POST /admin/checkin/lookup
          │               └─► Tra cứu thông tin khách theo checkin_code
          │               └─► Trả về thông tin + trạng thái hiện tại
          │
          │── Bước 2 ──► POST /admin/checkin/confirm
          │               └─► Xác nhận check-in → cập nhật DB
          │               └─► Trả về kết quả thành công / đã check-in rồi
          │
          └── Hoàn tác ──► POST /admin/checkin/undo
                          └─► Reset checked_in_at về null (nếu check-in nhầm)
                          └─► Ghi log hành động hoàn tác

================================================================================
PHẦN 2 — API 1: LOOKUP QR (Tra Cứu Mã)
================================================================================

ENDPOINT : POST /admin/checkin/lookup
MỤC ĐÍCH : Tra cứu thông tin khách dựa trên checkin_code vừa quét.
           Không thay đổi dữ liệu, chỉ đọc và trả về.

REQUEST BODY:
  {
    "checkin_code": "ATT-2026-X9K2P8AB"
  }

VALIDATION:
  - checkin_code: required | string | max:50

XỬ LÝ LOGIC:
  1. Tìm Attendee::where('checkin_code', $code)->with('event')->first()
  2. Nếu không tìm thấy → trả về lỗi 404
  3. Nếu tìm thấy → trả về thông tin đầy đủ + trạng thái check-in

RESPONSE — Thành công (200):
  {
    "status": "ok",
    "data": {
      "id"              : 42,
      "name"            : "Nguyễn Văn A",
      "email"           : "nguyenvana@example.com",
      "phone"           : "0901234567",
      "company"         : "ABC Corp",
      "ticket_type"     : "VIP",
      "event_name"      : "Tech Summit 2026",
      "event_date"      : "2026-09-15",
      "checkin_code"    : "ATT-2026-X9K2P8AB",
      "checkin_status"  : "not_checked_in",  // hoặc "checked_in"
      "checked_in_at"   : null,              // hoặc "2026-09-15 08:32:11"
      "checked_in_by"   : null              // hoặc { id, name }
    }
  }

RESPONSE — Không tìm thấy (404):
  {
    "status": "error",
    "code"  : "NOT_FOUND",
    "message": "Mã check-in không hợp lệ hoặc không tồn tại."
  }

RESPONSE — Sự kiện chưa diễn ra / đã kết thúc (422):
  {
    "status": "error",
    "code"  : "EVENT_NOT_ACTIVE",
    "message": "Sự kiện này chưa bắt đầu hoặc đã kết thúc."
  }

================================================================================
PHẦN 3 — API 2: CONFIRM CHECK-IN (Xác Nhận Check-in)
================================================================================

ENDPOINT : POST /admin/checkin/confirm
MỤC ĐÍCH : Xác nhận khách đã vào cổng — ghi nhận thời điểm và nhân viên quét.

REQUEST BODY:
  {
    "checkin_code": "ATT-2026-X9K2P8AB"
  }

VALIDATION:
  - checkin_code: required | string | exists:attendees,checkin_code

XỬ LÝ LOGIC:
  1. Tìm Attendee theo checkin_code
  2. Kiểm tra trạng thái:
     A. Nếu $attendee->checked_in_at != null
        → Đã check-in rồi → Trả về cảnh báo (không ghi đè)
     B. Nếu $attendee->status != 'confirmed'
        → Đơn chưa được duyệt → Trả về lỗi (không cho check-in)
     C. Nếu hợp lệ:
        → $attendee->update([
            'checked_in_at' => now(),
            'checked_in_by' => auth()->id(),
            'status'        => 'attended',
          ])
        → Ghi CheckinLog (xem Phần 6)
        → Trả về thành công

RESPONSE — Check-in thành công (200):
  {
    "status": "success",
    "code"  : "CHECKED_IN",
    "message": "Check-in thành công!",
    "data": {
      "name"          : "Nguyễn Văn A",
      "ticket_type"   : "VIP",
      "company"       : "ABC Corp",
      "checked_in_at" : "2026-09-15 08:32:11",
      "checked_in_by" : "Trần Thị B"
    }
  }

RESPONSE — Đã check-in rồi (409 Conflict):
  {
    "status": "warning",
    "code"  : "ALREADY_CHECKED_IN",
    "message": "Vé này đã được check-in trước đó.",
    "data": {
      "name"          : "Nguyễn Văn A",
      "checked_in_at" : "2026-09-15 08:15:44",
      "checked_in_by" : "Lê Văn C"
    }
  }

RESPONSE — Đơn chưa duyệt (403):
  {
    "status": "error",
    "code"  : "NOT_CONFIRMED",
    "message": "Đơn đăng ký của khách chưa được Ban tổ chức duyệt."
  }

RESPONSE — Mã không tồn tại (404):
  {
    "status": "error",
    "code"  : "NOT_FOUND",
    "message": "Mã check-in không hợp lệ."
  }

================================================================================
PHẦN 4 — API 3: UNDO CHECK-IN (Hoàn Tác Check-in)
================================================================================

ENDPOINT : POST /admin/checkin/undo
MỤC ĐÍCH : Hoàn tác check-in khi nhân viên quét nhầm hoặc khách chưa vào.
           Chỉ Admin cấp cao hoặc người có quyền mới thực hiện được.

REQUEST BODY:
  {
    "checkin_code" : "ATT-2026-X9K2P8AB",
    "reason"       : "Quét nhầm — khách chưa vào cổng"
  }

VALIDATION:
  - checkin_code : required | string | exists:attendees,checkin_code
  - reason       : required | string | min:5 | max:255

PHÂN QUYỀN:
  Middleware riêng: can:undo-checkin  (chỉ role: super-admin, event-manager)

XỬ LÝ LOGIC:
  1. Tìm Attendee theo checkin_code
  2. Kiểm tra: Nếu checked_in_at == null → Trả về lỗi (chưa check-in, không cần undo)
  3. Lưu thông tin check-in cũ vào CheckinLog với action = 'undo'
  4. Reset:
     $attendee->update([
       'checked_in_at' => null,
       'checked_in_by' => null,
       'status'        => 'confirmed',
     ])
  5. Ghi UndoLog: ai undo, lúc nào, lý do gì

RESPONSE — Hoàn tác thành công (200):
  {
    "status" : "success",
    "code"   : "UNDO_SUCCESS",
    "message": "Đã hoàn tác check-in cho khách Nguyễn Văn A.",
    "data": {
      "name"              : "Nguyễn Văn A",
      "previous_checkin"  : "2026-09-15 08:15:44",
      "undone_by"         : "Admin Nguyễn",
      "undone_at"         : "2026-09-15 08:17:02",
      "reason"            : "Quét nhầm — khách chưa vào cổng"
    }
  }

RESPONSE — Chưa check-in (422):
  {
    "status" : "error",
    "code"   : "NOT_CHECKED_IN",
    "message": "Khách này chưa check-in, không cần hoàn tác."
  }

RESPONSE — Không có quyền (403):
  {
    "status" : "error",
    "code"   : "FORBIDDEN",
    "message": "Bạn không có quyền hoàn tác check-in."
  }

11.3. LUỒNG JAVASCRIPT XỬ LÝ (FRONTEND FLOW)
--------------------------------------------------------------------------------

BƯỚC 1 — KHỞI TẠO CAMERA:
  const html5QrCode = new Html5Qrcode("qr-reader");
  html5QrCode.start(
    { facingMode: "environment" },  // Camera sau mặc định
    { fps: 10, qrbox: { width: 250, height: 250 } },
    onScanSuccess,
    onScanFailure
  );

BƯỚC 2 — KHI QUÉT ĐƯỢC MÃ (onScanSuccess):
  function onScanSuccess(decodedText) {
    // 1. Dừng camera tạm để tránh quét trùng
    html5QrCode.pause();

    // 2. Gọi API Lookup để xem thông tin khách
    fetch('/admin/checkin/lookup', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json', 'X-CSRF-TOKEN': csrfToken },
      body: JSON.stringify({ checkin_code: decodedText })
    })
    .then(res => res.json())
    .then(data => {
      if (data.status === 'ok') {
        // Hiển thị card thông tin + nút "Xác nhận Check-in"
        showResultCard(data.data);
      } else {
        // Hiển thị card lỗi
        showErrorCard(data.message);
        // Resume camera sau 3 giây
        setTimeout(() => html5QrCode.resume(), 3000);
      }
    });
  }

BƯỚC 3 — KHI NHẤN NÚT "XÁC NHẬN CHECK-IN":
  function confirmCheckin(checkinCode) {
    fetch('/admin/checkin/confirm', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json', 'X-CSRF-TOKEN': csrfToken },
      body: JSON.stringify({ checkin_code: checkinCode })
    })
    .then(res => res.json())
    .then(data => {
      if (data.code === 'CHECKED_IN') {
        // Cập nhật DB thành công → hiển thị card xanh
        showSuccessCard(data.data);
        playSound('success');
        updateStats();  // Cập nhật số liệu [Đã vào: X / Y]
        setTimeout(() => {
          hideResultCard();
          html5QrCode.resume();  // Sẵn sàng quét tiếp
        }, 4000);

      } else if (data.code === 'ALREADY_CHECKED_IN') {
        showWarningCard(data.data);
        playSound('warning');
      }
    });
  }

Khi API /admin/checkin/confirm xử lý thành công, các cột sau được UPDATE:

  Bảng: attendees

  Cột              | Giá trị cũ       | Giá trị mới
  -----------------+------------------+----------------------------------
  status           | 'confirmed'      | 'attended'           ← Đã vào sự kiện
  checked_in_at    | NULL             | now()                ← Thời điểm quét
  checked_in_by    | NULL             | auth()->id()         ← ID nhân viên quét

  Code PHP trong CheckinController@confirm:
    $attendee->update([
        'status'        => 'attended',
        'checked_in_at' => now(),
        'checked_in_by' => auth()->id(),
    ]);
